# LexOrchestrator Demo Guide

## Pre-Demo Checklist

Run these before every demo session:

```bash
npm run check:safety      # no forbidden terms or leaked secrets
npm run check:demo        # all routes, fixture, and MCP modules present
npm run lint              # no lint errors
npx tsc --noEmit          # no type errors
npm run build             # production build passes
npm run smoke:demo-path   # canonical workflow runs end-to-end
npm run smoke:mcp         # all 9 MCP tool modules respond correctly
```

All should exit 0 with no errors. If any fail, resolve before the demo.

Optional: seed fresh demo data if Supabase is configured:

```bash
npm run seed:litigation-demo
```

---

## Starting the Dev Server

```bash
npm run dev
```

Open `http://localhost:3000/draft`.

The app works without any env vars. With Supabase configured, workflow runs persist and appear in the dashboard history.

## Demo Steps

### Step 1 -- Draft form (`/draft`)

- The page shows a form: motion type, jurisdiction, court, judge, facts, desired output.
- Click **Load Demo** in the top right corner.
- This populates the canonical fixture: SDNY, motion to dismiss, Judge Rakoff, Aurora Analytics v. Northstar Retail Systems.
- Click **Start Draft**.
- The workflow submits and redirects to `/draft/[id]`.

**What to say:** "This kicks off the eight-agent pipeline. All agents run sequentially, each receiving what prior agents produced."

---

### Step 2 -- Draft workspace (`/draft/[id]`)

The page has two columns.

**Left column:**

- **Document Preview** (§ 02): The motion outline -- PRELIMINARY STATEMENT, STATEMENT OF RELEVANT FACTS, LEGAL STANDARD, ARGUMENT, CONCLUSION. Headings render with ruled separators. Prose in EB Garamond.
- **Authority Retrieved** (§ 04): Citations extracted from the draft, sourced from the retrieval agent.

**Right column (top to bottom):**

- **Verification Inspector** (§ 03): Each citation shows existence, quote, pin cite, proposition, and treatment status. Pass/warn/fail badges with a summary strip at the top.
- **Judge Brief** (§ 04b): If Judge Rakoff was found, shows style notes, citation preferences, argument guidance, and motion-type guidance.
- **Adversarial Review** (§ 05): Risk level badge plus strongest weaknesses, unsupported claims, and likely counterarguments from the red-team agent.
- **Local Rules Notes** (§ 06): Profile label (Southern District of New York), section check grid with pass/fail per required section, formatting and citation notes.
- **Eval Summary** (§ 07): Score bars for overall confidence, faithfulness, citation pass rate, retrieval coverage, local rules completeness, adversarial risk. Warnings if any. Link to full eval.

**Below columns:** Agent event feed -- chronological list of all agent events with latency.

**What to say:** "Every panel maps to a specific agent output. The verification inspector shows what the citation agent found. The judge brief is a DB lookup on cached profile data -- not generated by the LLM. The eval is deterministic scoring, not a subjective claim."

---

### Step 3 -- Technical inspection (`/workflows/[id]`)

Click **Technical Inspection** in the breadcrumb.

- § 01 Workflow Summary: status, confidence, faithfulness, motion type, jurisdiction.
- § 02 Agent Event Feed: all events in order -- run_started, agent_started, tool_call, tool_result, agent_completed, run_completed. Each shows latency.
- § 03 Draft Artifacts: raw artifact cards with type (outline, red_team_memo, local_rules_check, judge_brief, workflow_eval) and content preview.
- § 04 Citation Reports: full per-citation table with all sub-status columns.
- § 05 Eval Summary: final scores and output prose.

**What to say:** "This is the raw inspection layer. I can see every tool call, every agent event, the exact artifact stored in the DB, and the full citation report. Nothing is hidden."

---

### Step 4 -- Eval detail (`/evals/[id]`)

Click **Full Eval** from the draft workspace or **Eval** from the workflow inspection page.

- § 01 Score Summary: eight score bars (overall confidence, faithfulness, citation pass rate, retrieval coverage, local rules completeness, adversarial risk, judge coverage, unsupported claim risk).
- § 02 Quality Warnings: list of triggered warnings with amber text.
- § 03 Citation Quality: pass/warn/fail/unknown counts and pass rate.
- § 04 Authority Retrieval: total authorities, with-citation count, jurisdiction/court matches, average score, coverage label.
- § 05 Artifact Quality: hasDraft/hasAdversarial/hasLocalRules/hasJudgeBrief badges, section coverage bar, missing sections.
- § 06 Agent Runtime: total events, agents completed/failed, total latency, token count, estimated cost.

Click **Evals** in the nav to see the aggregate dashboard.

**What to say:** "The eval is computed from persisted DB rows, not from the in-flight agent outputs. The confidence formula is weighted and documented. I can point to every number."

---

### Step 5 -- MCP tools (optional, for technical audiences)

Show the MCP smoke test output:

```bash
npm run smoke:mcp
```

Explain the nine tools and the Claude Desktop config in `mcp/README.md`.

**What to say:** "The MCP server exposes the same pipeline modules as HTTP tools. Any MCP client -- Claude Desktop, Cursor, or a custom agent -- can call search, verify a citation, or run the full workflow by name."

## Failure Fallback Plan

| Failure | Recovery |
|---|---|
| Supabase unavailable | Demo still runs; outputs are deterministic. Workflow IDs are ephemeral UUIDs. Dashboard history is empty. Tell the audience the DB fallback is intentional and working. |
| No LLM key | Agents return deterministic fallback output. Motion outline has five sections with placeholder text. Quality scores will be lower. |
| `check:demo` fails | Read the output. If a file is missing, check git status. If a route is absent, the route file may have been renamed. |
| `smoke:mcp` fails | Check the tool that failed. Likely a dynamic import path issue or a missing module. Run `npx tsc --noEmit` to diagnose. |
| Port 3000 in use | `npm run dev -- -p 3001` |

## What Not to Say

- Do not claim the system provides legal advice.
- Do not claim citation verification is complete or authoritative.
- Do not claim judge brief output predicts outcomes.
- Do not claim local rules review constitutes compliance.
- Do not claim hallucination-free output.
- Do not mention any target employer by name.
